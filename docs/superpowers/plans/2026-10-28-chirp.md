# Chirp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Chirp, a deployed-ready Twitter clone (auth, posts, likes, reposts, replies, follows, search, images, notifications, profile editing) on Next.js + Supabase as a portfolio project.

**Architecture:** Next.js App Router with Server Components for reads and Server Actions for writes. All business rules that matter for security (authorization, counters, notifications, feed assembly) live in Postgres: RLS policies, triggers and two SQL functions, all tested with pgTAP. Client components exist only for interactivity (optimistic buttons, composer, image upload, theme).

**Tech Stack:** Next.js 15, React 19, TypeScript (strict), Tailwind CSS 4, shadcn/ui, `@supabase/ssr` + `@supabase/supabase-js` v2, Zod, Supabase CLI (local stack, migrations, `gen types`, `test db`), Vitest, Playwright, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-28-chirp-design.md`

## Global Constraints

- Node 20+; package manager npm; TypeScript `strict: true`; path alias `@/*` → `src/*`.
- UI copy in English.
- Username: lowercase, regex `^[a-z0-9_]{3,15}$`, unique.
- Display name 1–50 chars; bio ≤ 160 chars; post content ≤ 280 chars (counted as Unicode code points, same as Postgres `char_length`).
- A post must have trimmed non-empty content or an image.
- Images: buckets `avatars` and `post-images`, public read, write only under `{auth.uid()}/`, max 5 MB, MIME `image/jpeg, image/png, image/webp, image/gif`.
- Server Actions return `ActionResult<T>` and never throw to the client.
- The service role key is never imported by app code under `src/`.
- No `dangerouslySetInnerHTML` anywhere.
- Env vars: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_SITE_URL`, `DEMO_EMAIL`, `DEMO_PASSWORD` (`.env.example` documents all of them).
- Do not create cloud projects, deploy, or push to GitHub as part of this plan; Task 17 only documents those steps.
- Commit after every task with a conventional-commit message ending in the `Co-Authored-By` trailer.

## Review Focus

1. **Feed pagination with equal timestamps** — seed data and bulk inserts produce identical `activity_at`; "Load more" must not skip or duplicate items. The cursor is the pair `(activity_at, item_key)`, not `activity_at` alone (pinned in Task 5).
2. **GitHub usernames that don't fit the rules** — `Eren-Yıldız`, `ab`, `a_very_long_github_login_name`, or a name already taken must still produce a valid unique username (pinned in Task 2 and Task 7).
3. **Double clicks on like/repost/follow** — a second insert hits the primary key; the action must treat "already exists" as success and "already gone" on delete as success (pinned in Task 11).
4. **Whitespace-only or emoji-heavy posts** — `"   "` is rejected; `"😀" × 280` is accepted on both client and DB (pinned in Task 2 and Task 7).
5. **Deleted parents** — replying to a post that is then deleted leaves the reply visible with a "This post was deleted" placeholder instead of a crash; reposts of a deleted post disappear from feeds (pinned in Task 5 and Task 12).

Also: search terms containing `%` or `_` are matched literally (pinned in Task 13).
